# 01 · LaLaLand 毕业话剧平台 — 需求规格（PRD）

> Status: **v2 — 全部 20 个 GAP 已收敛，可进入 research/plan**
> 评估范围：介绍页 + 预约系统 + 后台管理 + 检票核验
> 用户：高三毕业话剧剧组（导演 / 主演 / 全校预约学生 / 检票员 / 管理员）
> 这是**纯需求文档**，不涉及具体实现方案。落地方案见 [02-implementation.md](file:///Users/chenm0m/LocalRepo/LaLaLandShow/.vibehub/notes/02-implementation.md)。

---

## 1. 背景

某中学（含小学/初中/高中）毕业前由高三班级排演 **La La Land** 英文话剧，仅 **演出一场**，场地为学校演艺厅。需为学生、检票员、剧组管理员提供一站式 Web 平台，承载介绍、预约、入场核验三个核心流程。

---

## 2. 角色与权限

| 角色 | 标识 | 权限 |
|------|------|------|
| **访客** | 无 | 仅可浏览介绍页 |
| **学生** | 7 位纯数字学号 | 可预约座位（受时间窗口控制）、查看/修改/释放自己座位、查看代约的座位 |
| **检票员** | 单一统一账号 + 密码（固定，部署时由环境变量预置） | 仅可进入核验界面、扫码 / 手动输入学号 / 查看实时人流 |
| **管理员** | 账号 + 密码（固定，部署时由环境变量预置） | 全部后台权限：座位管理、时间配置、统计 Dashboard、数据备份/回滚、操作日志、**+ 检票员的全部权限** |

> 学生**无密码**，学号即身份。学号同时是登录凭证与唯一标识。
> 管理员 / 检票员账号采用**固定账密**，不设置「修改密码」流程；密码由部署者用复杂字符串预置。
> **管理员是检票员的超集**：管理员可登录检票界面执行所有核验动作（用于演出当天临场支持）。

## 3. 介绍页（Marketing Landing）

### 3.1 结构（从上到下）
1. **Hero**：剧名大标题（占位英文 + 中文）+「**预约**」CTA 按钮
2. **演出倒计时**（目标时间后台可配）
3. **故事背景**
4. **故事概要**
5. **演员表**（角色 + 演员 + 班级 + 头像）
6. **剧照画廊**
7. （页脚）演出时间 / 地点 / 场次

### 3.2 视觉
- 配色：**紫色 + 深蓝 + 夕阳黄**（La La Land 经典）
- 风格：美观、略花哨，有电影感
- 全设备响应式：手机 / 平板 / PC 均完美

### 3.3 UX 期望
- 首屏 1 秒内可见 Hero + CTA
- 「预约」CTA 行为：
  - 未到开放预约时间 → 跳到「即将开放 / 倒计时」页
  - 已开放且未锁定 → 跳到学号登录
  - 已锁定 → 跳到「预约已截止」页，但已预约学生仍可登录看票根

### 3.4 内容运营
- 演出时间、地点、场次、剧名、演员表、剧照、倒计时目标 — **全部后台可配置或可上传**，前期用占位符开发

### 3.5 不做
- ❌ 排练花絮
- ❌ 中英双语切换
- ❌ 邮件/短信订阅
- ❌ **SEO 优化 / 搜索引擎收录**（页面 `<meta name="robots" content="noindex">`，仅校内私链传播）

## 4. 学号身份系统

### 4.1 学号
- 7 位纯数字（前端 + 后端双重校验）
- 示例：`1121040`（前 3 位 = 入学民国年，后 2 位 = 入学座号，中间 2 位含义待定 — 但平台不解析，只做格式校验）
- **唯一标识**：在系统中全局唯一

### 4.2 班级
- 纯数字，**长度不限**
- 示例：`903`（九年级三班）、`1103`（高二三班）、`1201`（高三一班）
- 由学生首次注册时填写

### 4.3 座号
- 学生本人在班级中的座号
- 自由 int，无范围限制（避免不同班配置不同的麻烦）

### 4.4 注册即首次登录
- **没有显式注册流程**
- 第一次输入学号 → 系统检测无记录 → 引导补充「班级 + 座号」→ 提交即创建账号
- 之后输入同样学号即视为登录

### 4.5 已被代约但本人尚未登录的学号
- 此学号在 DB 中已存在记录（含 `seat_id`），但 `class` / `seat_number` 为空
- 本人首次登录时，系统识别这种「半注册」状态：
  1. **强制补全班级 + 座号** 才能继续
  2. 在补全表单顶部**显示通知**：「您已被 *{代约人班级}{代约人座号}* 代约第 X 排第 Y 号座位」
  3. **不在补全页提供「接受 / 释放」按钮**；用户提交补全后进入主界面，再决定保留 / 释放 / 换座
- 座位**始终保留**，无须本人确认

## 5. 预约规则

### 5.1 时间窗口（3 段制，后台可配）

```
┌──────────────────┬──────────────────┬──────────────────┐
│ < 开放预约时间    │ 开放预约 → 锁定   │ 锁定 → 演出开始  │ ≥ 演出开始
├──────────────────┼──────────────────┼──────────────────┤
│ 仅介绍页         │ 可登录、选座、    │ 仅可登录、查看、 │ 全冻结
│ 选座入口关闭     │ 修改、换座、释放  │ 释放(取消)       │ 仅票根+核验
└──────────────────┴──────────────────┴──────────────────┘
```

### 5.2 座位限额
- 每个学号在系统内最多绑定 **1 个座位**
- 每个登录用户最多发起预约 **3 个座位**（1 本人 + 2 代约）

### 5.3 代约
- 预约 ≥ 2 座时，**必须**为每个非本人座位填入另一个 7 位学号
- 允许代约**未注册**的学号
- 代约**即生效**：被代约学号立即绑定该座位，无须本人确认
- 被代约学号若已被他人绑定/已自助预约 → 后到的代约请求**直接拒绝**

### 5.4 被代约者本人登录后
- 见到「您已被预约第 X 排第 Y 号 — 代约人 *{代约人班级}{代约人座号}*」
- 可以：
  - 接受（默认）：什么都不做
  - 释放：解绑该座位（不通知代约人；操作落日志）
  - 换座：释放后重新选
- **释放不设冷却期**，但每次操作必落操作日志（管理员可追溯）

### 5.5 代约时身份关系记录
- 每个被代约座位记录 `booked_by_student_id`（代约人学号）→ 用于追溯责任
- 被代约者登录后可在自己座位卡片上看到「代约人班级 + 座号」（不直接暴露学号，但管理员可在后台看到）

### 5.6 锁定后规则
- 不能新增 / 不能改 / 不能换
- **仍可释放**（你不来了，给别人留位）

### 5.7 演出开始后
- 全冻结：不能释放、不能修改、不能新增
- 仅可查看票根、二维码用于核验

## 6. 选座 UX

### 6.1 选座图
- 体验对标大麦 / 淘票票
- 三区清晰可见：**左区 / 中区 / 右区**（按面向舞台方向）
- 默认锁定 24 座（中区前 2 排 + 左区第 1 排）显示为「不可选」
- 已被他人预约：灰色 + 不可点击
- 自己已选：高亮色
- 可选：白底
- 鼠标悬停 / 触摸：显示「第 X 排 第 Y 号」
- 移动端：双指缩放 + 拖动

### 6.2 选座流程
1. 学生登录 → 若已有座位 → 展示当前座位 + 提供「修改」入口
2. **首次进入选座图前**：展示「预约规则横幅」（最多 3 座 / 代约即生效 / 锁定后只能释放 / 操作可追溯），点击「我已阅读」继续。**不强制勾选 checkbox**，仅展示
3. 进入选座图 → 点击空座位 → 加入待提交清单（左下角 chip 显示已选 N/3）
4. 选 ≥ 2 座时弹出「代约学号填写」表单，每座一个学号 + 默认本人座位预填
5. 点「确认预约」→ 后端原子提交 → 成功跳回票根页 / 失败提示具体冲突座位
6. **失败处理：** 整批失败而非部分成功，弹窗高亮冲突座位让用户重选

### 6.3 选座并发体验
- 当前选座图通过实时推送（SSE）保持新鲜，500 ms 内反映他人变更
- 别人抢走你正看的座位 → 该座位立即变灰，未确认者不影响
- **不做「临时持有/预占」机制**（提交即争抢，失败重选）：实现更简单、服务端无须维护持有 TTL、Redis 压力小
- **首次开放预约不做排队**：直接放开抢（385 座 vs ~1200 学生，排队无意义）。但 API 限流仍开（防恶意刷）

## 7. 票根与二维码

### 7.1 触发时机
- **锁定时间到达** → 系统为所有有效座位生成票根 + 二维码

### 7.2 票根（电子纪念）
- 内容：剧名 + 演出日期/时间 + 持票人班级 + 座号 + 座位号（X 排 Y 号）+ 剧照背景 + 二维码
- 视觉：La La Land 风格设计
- **底部小字：「本票本人有效，转让无效」**（声明性，不做技术防御）
- **可下载为 PNG 图片**（用于保存到相册 / 分享朋友圈）

### 7.3 二维码
- 内容：`student_id + seat_id + ticket_version + issued_at` 经服务端密钥 **HMAC-SHA256 签名**
- **必须同时含 student_id 与 seat_id**：仅含 seat_id 会让换座后旧码仍能扫开座位
- 允许复用（多次扫描有效）
- 验签失败直接拒绝
- 若学生在锁定前换过座位 → `ticket_version++`，旧二维码验签虽通过但 version 不匹配 → 拒绝；新二维码立即生效

## 8. 检票核验

### 8.1 登录
- 单一统一账号 + 固定密码（部署时环境变量预置）
- 允许多端同时登录（手机 / 平板 / PC）
- **管理员账号也可登录此界面**，权限相同

### 8.2 三种核验方式
都在同一界面，**三种方式都可触发"核准入场"**：

#### 方式 A：扫码（首选）
- 点扫码按钮 → 调起设备摄像头
- 解析 QR → 验签 → 查座位 → 显示结果卡片
- 卡片含「核准入场」大按钮，点了才算入场（避免误扫）

#### 方式 B：手动输入学号
- 输入框 + 数字键盘
- 提交后查 `seat_bookings` → 显示结果卡片
- 若有预约 → 卡片显示座位 + 「核准入场」按钮
- **若无预约 → 仍显示「该学号未预约，是否仍核准入场？」按钮**（应对临场加塞 / 特殊情况，但要落日志标记）

#### 方式 C：批量名单查询（兜底，演出当天系统故障预案）
- 检票员 / 管理员可下载完整 CSV 名单到手机
- 系统活着时仍走系统；系统挂了时人工对照 CSV
- 后台至少要保持活着用于查询（这是 §10.2 的底线）

### 8.3 结果卡片
- 学号 / 班级 / 座位号 / 持票人座号
- **首次入场** ✅ 绿底 或 **重复扫描** ⚠️ 黄底（显示首次扫描时间）
- **未预约** ❌ 红底 + 仍可手动核准的按钮
- **验签失败** ❌ 红底，无核准按钮
- 大字号区分通过 / 拒绝 / 已扫过

### 8.4 实时计数
- 顶部计数：已入场 X / 总票数 Y（按 distinct 学号统计）
- 30 秒自动刷新

### 8.5 扫描 / 入场事件
- 每次成功"核准入场"都记录：时间、操作账号（检票员或管理员）、学号、座位、入场方式（扫码/手输/未预约强批）、是否首次
- 重复扫描 / 未预约批准 / 验签失败 都进事件日志

### 8.6 异常
- 验签失败 → 红屏「无效票据」，不计数
- 学号不存在 / 未预约 → 红屏「未预约」+ 强批按钮（落日志）
- 网络断开 → 提示「网络异常，请用 CSV 名单兜底」
- v1 不做离线模式

## 9. 后台管理

### 9.1 登录
- 固定账号 + 固定密码（部署时由环境变量预置）
- 不提供修改密码功能（如需更换，重新部署）
- 允许多个管理员账号共存（但都是部署时预置）

### 9.2 座位管理（核心：演员/家长/老师/工作人员都在这里占位）
- 完整选座图（含锁定/已占/空闲三态）
- 点击任一座位看绑定信息（学号 / 班级 / 座号 / 代约人）
- 操作：
  - 改绑到另一学号
  - 释放
  - **强占（写入"占用标识符"自由文本：可写中文姓名、"演员-王某"、"家长-XX"、"老师-XX" 等，与真实学号绑定互斥）**
  - 永久锁定 / 解锁（如临时贵宾席）
- **使用场景：**
  - 演员、剧组工作人员预留座位
  - 家长、老师等无校学号人员入场
  - 学校领导 VIP 临时安排
- **强占已被学生预约的座位时：**
  - 强制弹窗二次确认「将释放原用户 *{学号 / 班级 / 座号}* 的预约，确定？」
  - 确认后释放原绑定 + 写新占用标识符 + 落操作日志
  - **原用户登录时，系统在其首页弹出通知**：「您的座位已被管理员调整 / 释放，请重新预约或联系剧组」
  - 默认期望：**几乎不强占学生已选的座位**（除特殊情况）

### 9.3 时间配置
- 开放预约时间
- 锁定时间
- 演出开始时间
- 倒计时目标时间（介绍页用）
- 时区固定 **UTC+8**

### 9.4 内容配置
- 剧名 / 副标题
- 演出地点、场次描述
- 故事背景 / 故事概要文本
- 演员表（增删改 + 头像上传）
- 剧照（上传 / 排序 / 删除）

### 9.5 统计 Dashboard
- 卡片：已注册人数 / 已预约人数 / 已入场人数（演出当天）/ 总票数 / 占用率
- 图表：
  - 注册人数按班分布柱图
  - 预约人数按班分布柱图
  - 三区座位占用率
  - 演出当天核验进度时间曲线
- 自动刷新（30s 一次）

### 9.6 数据导出
- 预约名单 CSV（学号 / 班级 / 座号 / 座位号 / 代约人）
- 注册名单 CSV
- 操作日志 CSV

### 9.7 操作日志
- 所有写操作记录：操作人、时间、动作、对象、前后值
- 可筛选 / 导出

### 9.8 备份与回滚
- 数据库定时全量备份（默认每日 1 次，保留 14 份，可配）
- 一键手动备份
- 一键从指定备份恢复（**带二次确认**）
- 备份文件保存在挂载卷，可下载

### 9.9 账号管理
- **不做账号管理界面**
- 管理员 / 检票员账号全部在 `docker-compose.yml` 的环境变量中预置
- 密码采用复杂字符串（部署者负责）
- 更换需重启容器

### 9.10 管理员可登录检票界面
- 后台首页有「进入检票界面」入口
- 等同检票员权限 + 自身管理员权限叠加（可同时操作两端）
- 演出当天若检票员不在或出问题，管理员可顶上

## 10. 非功能性需求

| 项 | 要求 |
|---|------|
| 部署 | Docker Compose，单 2C2G 服务器 |
| 网络 | 共用机房弹性带宽，峰值可达 200 Mbps（非独享，需注意削峰） |
| 容量 | 支撑 ~1200 学生抢 385 座 |
| 时区 | UTC+8 |
| HTTPS | 用户自行反代处理 |
| 端口 | 在 docker-compose.yml 中可配 |
| 备份 | 必须；周期可配 |
| 操作审计 | 全部写操作落库 |
| 实时性 | 选座图变更 500 ms 内推送 |
| 兼容 | iOS 15+ / Android 10+ / 主流桌面浏览器近 2 年版本 |
| 学生 Token 时效 | JWT 7 天滚动有效，过期静默重登（输入学号即恢复，无密码） |
| 多设备登录 | 同学号允许多设备同时在线，无设备绑定 |
| 演出当天宕机预案 | 后台数据库必须保持可读；CSV 名单可下载到检票员手机做人工核验兜底 |
| 数据隐私 | **登录页底部展示简短免责声明**：「本系统仅收集学号 / 班级 / 座号用于演出预约与入场核验，演出结束后将销毁个人数据」 |
| API 限流 | 单 IP 默认 5 req/s（基于 Redis），抢座接口豁免合理峰值 |
| SEO | 全站 noindex，仅校内私链传播 |
